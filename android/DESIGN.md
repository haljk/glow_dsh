## 1. 形态

单 Activity（`MainActivity`）承载全部界面，页面由一个 `when` 切换，不用 Navigation 组件。
出图跑在**前台服务**里，用户切走或锁屏任务继续；一次只有一个任务在跑。

四个页面与三个覆盖层：

| 页面 | 内容 |
| --- | --- |
| 工作台 `WORKBENCH` | 场景选择、描述输入、输出设置摘要、以前做的（最近 8 张）、底部操作条 |
| 全部作品 `LIBRARY` | 全部 / 已归档 两个筛选，长按进多选，批量归档/删除 |
| 任务 `JOBS` | 当前任务 + 最近记录（读磁盘，跨进程重启仍在） |
| 设置 `SETTINGS` | 电脑地址、高级折叠、等待时长、保留参考图副本、扫码配对 |

覆盖层：查看器（全屏）、输出设置弹层、角色选择、预设选择、指令预览弹层、
扫码预览、配置二维码弹窗、删除确认弹窗。

## 2. 界面规范

### 2.1 颜色

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底 `background` | `#F6F6F9` | `#111115` |
| 卡片 `surface` | `#FFFFFF` | `#1E1E25` |
| 主色 `primary` | `#5B4CF0` | `#B8ACFF` |
| 选中填充 `primaryContainer` | `#E7E3FF` | `#3E3592` |
| 选中文字 `onPrimaryContainer` | `#21166B` | `#EEEAFF` |
| 描边 `outline` | `#8A8A96` | `#7C7B89` |
| 发丝线 `outlineVariant` | `#E6E6EC` | `#2D2D36` |
| 错误 `error` | `#C4311F` | `#FF9C8F` |
| 成功（语义色） | `#1F8A4C` | `#6FD394` |

`surfaceContainer*` 五个角色全部指向卡片色，因此弹层、弹窗、菜单与卡片同色，浮层不再另起一层紫。

**紫色的用法是排他的**：只用于「选中态」和「主操作」。页面底、卡片、边框都不用紫色，
否则选中态和普通容器无法区分。

### 2.2 排版与形状

字号只有四档：24 / 17 / 14 / 13 sp。

| 元素 | 圆角 | 处理 |
| --- | --- | --- |
| 卡片 `GlowCard` | 20dp | 浅色：无描边 + 2dp 阴影；深色：1dp 发丝线（近黑上阴影看不见） |
| 选项 chip | 10dp | 未选 1dp `outline`；选中 1.5dp `primary` + 浅紫填充 + ✓ |
| 场景卡 | 16dp | 选中 = 浅紫填充 + ✓，**不用描边**（描边与输入框聚焦态撞车） |
| 缩略图 | 16dp | 与卡片同一档 |
| 主按钮 | 14dp | 实心 `primary` + 白字 |
| 弹层 | 28dp（M3 默认） | 白面 |

页面左右轨统一 16dp。输入框描边用 `outline`（对白 3.4:1），禁用态按钮文字 78% 墨色（3.5:1），
时间戳用完整 `onSurfaceVariant`（6.0:1）。

### 2.3 顶栏

标题「阁楼」+ 右侧三件套：任务胶囊（有任务时）/「任务」入口（无任务时）、连接状态胶囊、
齿轮（进设置）。

连接胶囊三态：已连接（绿点）、未连接（红点，点它进设置）、检查中（灰点）。

## 3. 三种场景

| 场景 | 参考图上限 | 控件 |
| --- | --- | --- |
| 一句话出图 `TEXT` | 0 | 描述框 + 输出设置 |
| 照片精修 `RETOUCH` | 2 | 参考图（第 1 张为主体）+ 预设 + 补充描述 |
| 多图合成 `COMBINE` | 5 | 多张参考图（各带角色）+ 怎么合 + 输出设置 |

- **草稿按场景分开**：三个场景各存一份描述，切换不互相覆盖。
- **参考图角色默认**：第 1 张 `主体`，第 2 张起 `场景`，可逐张改（6 种角色）。
- 缩略图左上角有编号角标，与指令里的「图 1 / 图 2」对应。

## 4. 指令合成（`core/`）

编辑类指令由四段拼成：

```
以 <Picture 1> 为主体，完整保留其身份、面部特征、肤色、发型、表情、姿态、镜头角度；
另外，{用户描述}；
除上述明确指定的改动之外，其他一切保持不变：{冻结清单}；
不增加也不删除任何物体。
```

- **预设**（9 个：换背景、换衣服、换发型、换表情、换光线、清理杂物、白底抠图、修复老照片、证件照）
  各自声明「允许改动哪几项」。
- **冻结清单**由总表减去预设允许项生成（`Preserve.kt`），所以「换光线」不会一边改光一边锁光。
- **角色**（6 种）决定句式里怎么称呼这张参考图。
- 上限：16 张参考图（`MAX_REFERENCES`），界面按场景限制得更严。

**不提供自动改写**：润色只在用户主动点「帮我写」时发生，结果写回输入框、可继续编辑，
按用户输入对待。系统约束独立于是否润色。

## 5. 输出尺寸

两套路径，按场景选：

**固定比例（`OutputTable.kt`）**——文生图，或参考图模式里手动指定比例：

| 比例 | 快速 | 推荐 | 高清 |
| --- | --- | --- | --- |
| 1:1 | 768×768 | 1024×1024 | 1536×1536 |
| 3:4 | 672×896 | 896×1216 | 1152×1536 |
| 4:3 | 896×672 | 1216×896 | 1536×1152 |
| 9:16 | 576×1024 | 864×1536 | 1152×2048 |
| 16:9 | 1024×576 | 1536×864 | 2048×1152 |

**跟随原图（`SizeFit.kt`）**——参考图模式的默认项：按第一张参考图的真实比例贴合，
边吸附到 32 的倍数、落在 256–2048 内，清晰度只决定像素预算（640² / 1024² / 1440²）。
非标准比例（如 4:5）原样保留，不吸附到五个标准比例。

张数 1 / 2 只对文生图开放，编辑类固定 1 张。

界面上尺寸收成一行摘要：`1:1 · 推荐 · 1 张 …… 1024×1024 ›`，点开才是选择器。

## 6. 任务模型与持久化

### 6.1 两个层次

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 内存快照 `JobRegistry` | 单例 StateFlow | 界面实时显示：阶段、百分比、eta、排队位 |
| 任务记录 `TaskStore` | `files/tasks/<id>.json` | 滚动存档：状态轨迹、产出作品名、原图副本 |

每次状态变化都**写穿**到磁盘，不依赖界面是否在观察。

### 6.2 阶段

`SUBMITTING → QUEUED → RUNNING → FETCHING → DONE | FAILED`，
取消时为 `已取消`（排队中真取消）或 `已放弃`（已开跑，结果不保存）。

### 6.3 任务记录字段

`id`、`remoteId`、`createdAt`、`updatedAt`、`status`、`summary`、`note`、`prompt`、
`presetId`、`size`、`count`、`percent`、`etaSeconds`、`message`、`resultNames[]`、
`referenceFiles[]`。

### 6.4 原图副本存在哪

提交那一刻把参考图复制进 `files/tasks/<id>/ref-N.png`，早于任何授权失效。
作品自带的副本（`files/gallery/<base>.ref-N.png`）仍按设置决定保不保留；
查看器取原图时**先看作品、再看任务**，两处都没有才提示无法对比。

## 7. 出图服务接入

两套接口，默认队列：

| 模式 | 提交 | 跟进 | 结果 |
| --- | --- | --- | --- |
| 队列 `queue` | `POST /v1/images/jobs`（文生图）／`/v1/images/jobs/edits`（编辑） | `GET /v1/images/jobs/{id}` 每 4 秒 | 按返回的 URL 下载 |
| 同步 `sync` | `POST /v1/images/generations`／`/v1/images/edits` | 一个请求等到出图 | 响应体直接带图 |

取消：`POST /v1/images/jobs/{id}/cancel`。

### 7.1 超时与轮询

- **排队模式没有 wall-clock 截止**：一直轮询到服务端给出成功、失败或取消。
  「出图最长」这项设置只约束同步模式的单次请求。
- 唯一中断条件是**连续 45 次（约 3 分钟）读不到任务进度**，属于服务异常而非任务慢。
- 客户端分三套 OkHttp：长请求（读超时按设置）、提交（30 秒）、取图（180 秒），
  避免把长超时套到下载上。

### 7.2 取消的语义

| 状态 | 按下取消 | 结果 |
| --- | --- | --- |
| 排队中 | 服务端接受，位子让出 | 提示「已取消，模型还没开始」 |
| 已开跑 | 服务端返回 409 | 任务做完但**结果不入库**，提示「已经开跑，做完不保存」 |

409 是正常答案，不当作错误弹窗。

### 7.3 失败

失败走底部弹条：原因 + 「重试」。任务页里该记录标「没成功」并保留原因。

## 8. 本地存储

```
files/
├─ gallery/
│  ├─ <base>.png           结果
│  ├─ <base>.json          描述、尺寸、种子、archived、refFiles、isEdit、queueJobId
│  └─ <base>.ref-N.png     参考图副本（受「保留参考图副本」控制）
├─ tasks/
│  ├─ <id>.json            任务记录
│  └─ <id>/ref-N.png       原图副本（提交时复制）
├─ settings.json
├─ favorites.json          常用提示词，上限 5
└─ pending-job.json        进行中的任务，用于进程被杀后恢复
```

`<base>` 形如 `20261125-095139-1571414720`（时间 + 种子）。

删除一个结果会连带删除 `.png`、`.json` 与所有 `.ref-N.png`；归档只改 `archived` 字段，不动文件。

## 9. 看图与对比

查看器是全屏深色壳，系统栏图标强制白色（浅色主题下也一样，否则图标在深色壳上消失）。

| 模式 | 行为 |
| --- | --- |
| 切换 `SWITCH` | 一次显示一张，单指左右滑动切换原图/结果 |
| 并排 `SIDE` | 左右各一栏，中间 2dp 缝隙 |
| 滑动 `WIPE` | 叠放，拖动分界线；分界线只画在照片范围内 |

**三种模式都支持双指缩放**（1–5 倍）。手势层只识别双指，单指滑动仍归切换与分界线，
两者不互相吞掉。

原图/结果标签放在照片下沿 +24dp、贴屏幕左右轨，不压在照片上（压在照片上对比度不足）。

没有原图时，查看器写明是哪种情况：文生图无原图／副本已不在／没有保留副本。
图库里有原图的缩略图带「对比」角标，点它直接进并排。

## 10. 扫码配对

二维码内容是一段可读的版本化文本，不含任何凭据：

```
glow://config?v=1&host=100.99.63.62&img=9742&llm=9739&legacy=9741&mode=queue&model=default_model&timeout=std
```

- **生成**：设置页把当前配置渲染成二维码，可存进系统相册（`Pictures/Glow`，走 MediaStore）。
- **导入**：相机预览解码，解出后**先列差异**（旧值 → 新值，只列真正变化的项），确认才写入。
- **校验**：前缀不对、版本高于本机、缺少地址都会给出具体原因。
- **权限**：只在点「扫码导入」时申请相机权限；拒绝后提示可手动填写，不再自动重复申请。
  相机特性声明为 `required=false`。

## 12. 已知限制

1. **深色模式**只截过工作台与输出设置两屏，其余页面未逐一核对。
2. **扫码导入**的端到端链路（生成 → 另一块屏幕显示 → 扫描 → 差异 → 写入）未做过完整复现，
   验证到的是权限申请、相机预览与解码界面。
3. **弹窗与弹层的遮罩深浅不同**：二次确认走平台 `AlertDialog`（0.6），
   底部弹层走 M3 默认（0.32），两种手感并存。
4. **双指缩放无法用 adb 脚本验证**（只能注入单指），需真机操作确认。
5. **任务记录不会自动清理**：任务页有「清空记录」（只删记录与任务目录，不影响作品），
   原图副本会随任务数增长占磁盘。
6. 一次只跑一个任务；队列里若有别人的任务，只能等。
