## 1. 产品定位

**给非专业用户的一个"少调参数、多出成品"的本地图像工作台。**

它不是一个通用图像编辑器，也不是 prompt 编辑器。它把三件具体的事做成三条固定路径，并把一台局域网模型服务的"真实可用能力"翻译成人话。

### 1.1 不做什么

明确排除，以免功能蔓延：

- 不做图层、蒙版、笔刷等像素级编辑
- 不做多模型切换（换模型要走另一条链路）
- 不做账号、云端同步、分享链接
- 不做密码/权限（归档只是"收起来"，不是保密）

### 1.2 命名

英文 **Glow**（光、发光），中文 **阁楼**（一个人的小工作室）。二者谐音，且分别对应"图像的光感"与"个人创作空间"，合起来正好是"在自己的阁楼里让图亮起来"。

## 2. 目标用户与场景

### 2.1 用户画像

- 会用电脑、会打字，但**不懂**「采样步数」「guidance」「负向提示词」「CFG」这类词
- 有真实的图要处理：社交配图、产品图、个人照片、素材图
- 能接受"等几分钟"，但不能接受"等完发现白等了"
- 单机单用户，不需要协作

### 2.2 三条主路径

| 场景 | 用户手里有什么 | 用户想做什么 |
| --- | --- | --- |
| ① 写一句话出图 | 什么都没有 | 从零得到一张图 |
| ② 单图精修 | 一张照片 | 换背景/换衣服/换发型…，**别的地方别动** |
| ③ 多图合成 | 两张以上素材 | 把 A 的人放进 B 的景、穿 C 的衣服 |

三条路径共用同一套尺寸、种子、任务与结果管理。

## 3. 设计原则

五条原则，每条都由一个具体的服务端事实或工程约束倒推而来，不是口号。

| 原则 | 来源事实 | 落地方式 |
| --- | --- | --- |
| **只暴露真的能调的东西** | 采样步数与 guidance 是固定值，负向提示词被静默忽略 | 不做滑杆；把固定项以只读方式展示并解释原因 |
| **等待不能挂在请求上** | 一次精修几分钟，任何短超时都会让结果作废 | 提交只拿任务号，长耗时在后台跑，页面只轮询 |
| **任务慢不是失败** | 排队与出图的时间由服务端决定 | 排队模式没有总时长上限，只在"连续读不到进度"时才收手 |
| **替用户写他不会写的那句话** | "只改指定部分、其余锁住"是精修成败关键，普通人写不出来 | 9 个预设各自携带指令 + 按预设生成的冻结清单 |
| **比例和清晰度是两件事** | 编辑耗时由参考图张数主导，与画布尺寸关系不大 | 比例跟原图、清晰度选档，互不干扰 |
| **不承诺做不到的事** | 无蒙版 → 无法"物理保证"不变 | 界面明说"提示词约束，不是蒙版重绘" |

## 4. 信息架构

侧边栏一个入口，点开是主面板。左列负责「选场景 → 填素材 → 提交」，右侧负责「任务与作品」。

```
┌──────────────────────────────────────────────────────────┐
│ 阁楼                                [任务] [已连接] [齿轮] │
├────────────────────────┬─────────────────────────────────┤
│ ① 先选做什么            │  任务：进行中 + 最近记录          │
│  ┌─ 写一句话出图       │                                 │
│  ├─ 拿一张照片精修      │  本次结果                        │
│  └─ 多张图合在一起      │  ┌────┐ ┌────┐ ┌────┐           │
│ ② 写一句描述 / 放图片    │  │ 图 │ │ 图 │ │ 图 │           │
│   （随场景变化的控件）    │  └────┘ └────┘ └────┘           │
│   常用提示词            │                                 │
│   输出尺寸（一行摘要）    │  以前做的                        │
│                        │  ┌────┐ ┌────┐                 │
│ ─────────────────────  │                                 │
│ ③ 开始 [生成图片]        │  归档箱                          │
└────────────────────────┴─────────────────────────────────┘
   顶栏右侧：任务胶囊 · 连接状态 · 齿轮（设置弹层）
```

**提交按钮固定钉在左列底部**，不随内容滚走——精修场景的控件能堆到很高，按钮若跟着滚会落到首屏之外。这条约束在窄窗口下同样成立（左右改为上下堆叠）。

界面用 ①②③ 三步引导，降低"这么多控件从哪开始"的压力。

## 5. 功能设计（意图层）

### 5.1 场景一 · 写一句话出图

用户只有一个念头，没有素材。产品要做的是把大白话补成模型看得懂的完整描述——补环境、光线、构图、镜头与画质，删掉"高质量""杰作"这类没有信息量的词——而不是把用户推去学写 prompt。

风格/光线/镜头的小标签是为了降低"从空白开始"的门槛：点一下就把一个具体词缀进描述里。

### 5.2 场景二 · 单图精修

这一档的产品核心不是"能改什么"，而是**"别的地方别动"**。

换背景、换衣服这类操作，难点在保人：脸、发型、姿态、身份要留住，只有被点名的那几项可以变。普通人写不出这种"只改这里、其余锁住"的句子，所以做成 9 个预设：换背景、换衣服、换发型、微调表情、换光线、去掉杂物、抠图纯色底、老照片修复、证件照换底色。

- 每个预设声明"允许改动哪几项"，**保持不变的那句由总表减去这几项生成**。
  早期版本用一句固定的"其余不变"，结果「换光线」预设一边说改光线、一边说光照不变，
  模型按它最后读到的那半句执行。现在这个矛盾从结构上不存在。
- 主体句也吃同一份允许项：选「换表情」时，主体句里不会再出现"保留表情"。
- 面板上会直接写「会改动：…」，剩下没列的才是被锁住的——让这句约束对用户可见，而不是藏在代码里。

### 5.3 场景三 · 多图合成

模型不知道"哪张该留着、哪张该借用"。用户必须逐张声明用途（主体／背景／服装／色调与画风／构图与机位／局部细节），系统据此写出一条精确的指令。

"看看会怎么告诉模型"这一层透明是刻意的：用户看不懂模型内部，但能看懂中文，看懂了才敢用。

### 5.4 提示词助手

接本地 LLM，但**不做自动改写**：润色只在用户主动点「帮我写」时发生，结果写回输入框、可继续编辑，此后按用户输入对待。

所有改写都受同一套硬性约束：

1. 只输出正文，不要解释与引号包裹
2. 必须落到可观察的视觉事实（材质、光线方向、构图、镜头）
3. 禁空话（"高质量""杰作""8K"）
4. **所有排除要求改写成正向陈述**，不得出现"不要/避免/没有/no/without/avoid"
5. 画面文字用引号原样写出并指定位置

第 4 条不是风格偏好，而是因为负向提示词在这个模型上无效——负向表述写进去等于没写。

### 5.5 尺寸：让用户选比例，别让他算像素

用户心里想的是"我要一张竖图"，不是"896×1216"。

- **文生图**：五个比例 × 三档清晰度，一眼能选完。
- **编辑**：默认跟随原图的比例，用户只选清晰度。原图是什么形状，出来就是什么形状，4:5 这类非标准比例也照原样保留。
- **清晰度**只决定像素预算，永远不改比例。

这样切开之后，"要一张什么形状的图"和"要多清晰"变成两个独立问题，用户不用再自己算宽高、也不会一改清晰度就把构图改掉。

### 5.6 结果、对比与归档

- 点缩略图进全屏；有参考图的编辑结果**直接进对比视图**——用户最想确认的就是"改得像不像"。
- 对比有两种看法：并排（整体看）与滑动（看哪里被悄悄改了）。滑动对比的分界线只画在照片上。
- **归档只是隐藏**，文件不删。目的是让工作台保持干净，不是保密。
- 删除要给二次确认，并写清会一起删掉什么（图、描述、参考图副本）。删了恢复不了，所以不提供"撤销"这种假承诺。
- 找不到原图时要说清是哪一种情况（本来就没有／副本被删了／设置里关掉了保留），不笼统说一句"无原图"。

### 5.7 任务与等待

用户对等待的容忍度取决于"我知道它还在动"。

- 提交即返回，任务在后台排队；切页面、刷新、最小化都不中断。
- 任务记录落盘，**关掉再打开还在**——"我刚提交的那张去哪了"是这类工具最容易丢信任的地方。
- 取消要分两种说：还在排队（真的没跑）与已经开跑（停不下来，跑完结果不要）。合并成一句"取消成功"，等于骗人。
- 排队模式**没有总时长上限**。任务慢不构成放弃的理由；只有"连续读不到进度"这种连接问题才收手。

## 6. 能力边界

由服务端事实倒推，不是产品自设的限制：

- 采样步数与 guidance 是固定值，负向提示词被忽略 → 所以界面上不做这些开关。
- 一次出图最多 2 张。
- 服务端支持更多参考图，但**产品主动收紧到精修 2 张、合成 5 张**——每多一张参考图就多一份等待，张数一多，"大约要等多久"这个预估就彻底失效。
- 出图服务同一时刻只跑一个任务。连续提交会自动排队，等待叠加。
- 结果文件在服务端只保留有限天数，插件成功即转存本地，不依赖服务端地址长期有效。

## 7. 安全与定位的关系

插件只服务本机单用户：接口只接受本机访问，没有账号体系，归档不设密码。

这不是偷懒，而是定位决定的：这些图片本来就躺在使用者的磁盘上，本机上的任何进程本来就能直接读写它们。在这个前提下加登录框只是表演。**要给别人访问，正确做法是另做一个带正式认证的后端**，而不是把本机接口放开——界面里也是这么写的。

---

## 8. 已知限制（产品层）

1. **"别的地方不动"是提示词约束，不是蒙版重绘**。换背景后脸、发型、服装、姿态都保留，但脸型仍可能轻微漂移；关键用途应多出几张挑。
2. 出图服务同一时刻只跑一个任务，连续提交会排队，等待时间会累积；界面上的剩余时间是估算值。
3. 已经开始的那一轮生成停不下来。取消只能在排队阶段真取消；开跑之后取消等于做完丢弃结果。
4. 小尺寸对编辑是毁灭性的，推荐档以下只当预览。
5. 换背景/抠图时，复杂发丝边缘可能出现毛边。
6. 关掉整个应用会中断进行中的生成（已出图的不受影响）。
7. 界面文案以中文为主，未做完整英文版。
8. 参考图副本会占磁盘，删除结果时一并清理。

## 9. 未实现 / 后续路线

明确未做，供下一期取舍：

| 方向 | 价值 | 前置条件 |
| --- | --- | --- |
| **真正的局部重绘（蒙版）** | 让"别的地方不动"从建议变成保证 | 需要带蒙版通道的推理链路，是另一条工程线 |
| Agent 工具（对话里直接出图） | 不必打开面板 | Host 逻辑已可复用，需暴露 3–4 个工具 |
| 前端完整 i18n | 英文用户可用 | 需把散落文案全部收进字典 |
| 4K 输出 | 打印级 | 需要服务端开启 4K 通道 |
| 多画廊目录切换 | 分项目归档 | 设置已支持换目录，缺迁移体验 |
| 归档密码保护 | 真"藏起来" | 需密钥管理，与当前"只是收起来"定位冲突，需先定语义 |
