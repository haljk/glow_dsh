## 队列改造（2026-11-23）

服务端把 `:9741` 同步接口包了一层队列 `:9742`，Android 默认改走队列，同步保留可回退。

| 切换指南要求 | 实现 | 证据 |
| --- | --- | --- |
| 提交返回 202 并拿到 id | `ModelClient.submitTextToImage/submitEdit`，解析 `id` | `QueueClientTest`（15 例） |
| 轮询能拿到 queued/running/succeeded | `GenerationService` 每 4 秒查一次 | 日志采样：`排队中` → `正在生成 约 13%` → `完成` |
| 成功后下载并转存 | `fetchResult` 后立刻 `GalleryStore.save` | 产物 `20261123-133309-1411923315.json` |
| `n=2` 分别取 `result.png` / `result-1.png` | `fallbackItems` 按索引拼 URL | `QueueClientTest`「a finished task lists its images」 |
| 相同 `Idempotency-Key` 不产生第二张 | 提交带键，重试复用 | `QueueClientTest`「submit sends the documented body」 |
| 429 有延迟重提；4xx 不重试 | `QueueBusy.retryAfterMs` 退避；`QueueRejected` 直接报错 | 契约测试各一例 |
| `failed` 能展示上游错误 | `state.error` 直接进横幅 | `QueueClientTest`「a failed task keeps the model's own words」 |
| 客户端重启能用已有 `job_id` 续查 | `pending-job.json` + `resumePendingJob()` | 见下 |
| 回滚开关 | 设置页「队列 / 同步」切换，两个地址都保存 | 设置页截图 |

**真机验证记录**

- 队列模式一次 1024² 真实生成：`job_20261123-133205_ecb0f2c1`，61.65 秒，产物元数据里带 `queueJobId`。
- 计数器：`succeeded` 36 → 37，只增一次。
- **重启续查**：提交 `job_20261123-133354_3ed5bb93` 后 6 秒 `force-stop` 杀进程；
  重开 App 横幅直接显示 `正在生成 · 已等 8 秒`，队列侧仍 `running=1`、任务号不变，
  说明没有重新提交；完成后队列 `succeeded` 只 +1，产物带同一个 `queueJobId`。
- 进度真实跳动：每 3 秒采样得到 `约 6% → 13% → 19% → 32% → 39% → 52% → 58% → 71%`。

- **真实精修走队列**：`job_20261123-135330_04c98e63`（`kind=edit`，`references=1`），
  `queued → running（2% → 59%）→ succeeded`，222.94 秒；产物 1024×1024，
  元数据带同一个 `queueJobId`、`note` 与参考图副本 `*.ref-1.png`。这是切换指南里最容易
  被忽略的一条——multipart 提交与长任务组合。
- **取消排队中的任务**：先用一次 1024 任务占住队列，再从 App 提交 512，此时队列 `queued`；
  点「不再等」后队列侧变 `canceled`，横幅显示「已取消 / 已取消，模型还没开始」。
  `running` 时取消被服务端拒绝（409），对应单测 `cancelling a running task is refused with 409`。

**已知取舍**

- 续查时 App 已经拿不到相册授权（photo picker 的读取权限不跨进程），所以恢复的精修任务
  只保留结果、不再补参考图副本；对比视图此时只显示结果。
- 进度是服务端按历史耗时估的，界面写「约 X%」，不承诺精确。
- 结果只保留 7 天，App 在 `succeeded` 后立刻下载，不留「只存 URL」的路径。

素材处理的两个坑（都在这轮踩到）：

1. **设计稿自带圆角方形外框**。直接裁切会把 mockup 的边留在图标里，圆形遮罩下露出一圈浅色。做法是裁到内容边界后，用同一半径的圆角做 alpha，角上交给背景渐变补。
2. **启动屏图标会被平台裁成圆形**。用整张方图当启动图标时，圆盘边缘与启动底色对不上，出现一个浅色圆。改成抠掉藏青底、只留屋顶与暖窗的透明标记，接缝消失。

已知限制：主题图标（单色层）在模拟器上无法验证——需要用户在系统里开启“主题图标”，且不同 ROM 的着色策略不同。该层只用矢量剪影，没有依赖渐变，按规范实现。

## 版本号与保存反馈（2026-11-24）

**版本号自动推导。** 之前只有改图标那一次手动从 1.0 提到 1.1，之后连发三个包都叫 1.1——
手机上装的是哪个包，从界面和文件名都看不出来，而厂商安装器还可能把同版本号当成"已装过"而跳过。

现在 `tools/build-android.ps1` 从 git 取两个值并传给 Gradle：

- `versionCode` = `git rev-list --count HEAD`（只增不减）
- `versionName` = `1.1.<提交数>-<短 SHA>`，例如 `1.1.30-a349796`

设置页底部显示 `版本 1.1.30 · a349796`，直接来自 `PackageManager`，不接数据线也能确认装的是哪一版。
裸跑 `gradle assemble` 时回退到 `versionCode=1` / `versionName=1.1-unknown`，不会悄悄产出同号包。

**保存反馈。** 此前点「保存并生效」后界面没有任何变化：配置写盘了、探测跑了，但状态点本来就是"已连接"，
看起来像没反应。现在有四种状态：

| 状态 | 按钮 | 反馈行 | 状态行 |
| --- | --- | --- | --- |
| 探测中 | 「正在保存…」灰底但 6.02:1 可读 | `已保存，正在测试…` | 灰点 +「测试中…」+ 地址 |
| 两台都通 | 恢复 | `已保存，两台服务都连上了`（绿） | 绿点 +「已连接」+ 地址 |
| 单台失败 | 恢复 | `已保存，但出图服务连不上`（红） | 红点 +「连不上」+「地址 无响应」 |
| 两台都失败 | 恢复 | `已保存，但两台服务都连不上`（红） | 同上 |

真机验证（`:9750` 填错 → 不可达 `10.255.255.1` 拖慢探测）：

- 成功态：`已保存，两台服务都连上了` + 两条 `已连接` + 各自地址
- 失败态：`已保存，但出图服务连不上` + `出图服务 · 连不上` + `http://10.255.255.1:9742 无响应`，
  提示词服务仍显示已连接
- 探测态：灰色按钮「正在保存…」、反馈 `已保存，正在测试…`、两行 `测试中…`、地址保留
- 探测态按钮盒仍为 x 42–1037，与落定态逐像素一致（不位移）

## 两个只在真机才现形的坑（已修，留档）

- **通知渠道重要性改不了。** 系统侧的渠道在 `pm clear` 与 App 升级后都保留，只有换 id 才生效。
  渠道因此从 `glow_jobs` 迁到 `glow_jobs_v2`（DEFAULT + 显式关声音与振动），并删除旧渠道；
  效果是通知从「Silent」分组里移出来，成为一条正常的进行中通知。
- **状态栏那一格另有原因，不是渠道，是图标。** `ic_stat_glow` 最初用 `strokeColor` 画屋顶与
  窗框，通知面板里看正常，状态栏却一个像素都没有：小图标是 alpha 蒙版，18dp 下两单位描边
  只剩一像素抗锯齿。改成填充剪影、用 `evenOdd` 把窗口挖空后立即出现。
  判据（窗口别设错）：状态栏**时钟与菱形之间**应出现约 **22px** 宽的实心字形，1080 宽下位于 **x≈193..214**。
  逐簇实测：`54-statusbar-crop.png`（描边版）该位置整段为空，时钟之后直接是菱形 `186..221`；
  `62-statusbar-filled-crop.png`（实心版）多出 `193..214` 这一簇，菱形被挤到 `244..279`。

  两个坑都记在这里：① 最初把窗口设成 `x≥230`，恰好把房子排除、把右移后的菱形框了进来，
  读出的 `0 → 36` 全是菱形，数字纯属巧合；② 任务开始 5 秒时截图可能抢在通知发布之前，同样读 0。
  **量这一格要给通知一秒，并按「时钟右侧、菱形左侧」取窗口，不要从固定 x 起算。**
  `notif-at-shot.txt` 是同一条 shell 里先 dump 再截图的记录，证明通知确实在场。

  注意：**不要**去把渠道调成 `IMPORTANCE_MIN` 试图修这一条——那是隐藏状态栏图标，方向相反。

## 与原型不同、且有据可依的地方

1. **描述框回车仍换行**（原型是回车即生成）。描述常写成多行，误触一次就是几分钟排队。
2. **不显示连接延迟**（原型有「延迟 38 ms」）。省掉一个用户会拿去和 ping 对比的数字。
3. **不做「自动润色描述」开关**。润色本来就是手动触发的，结果回输入框可编辑、视为用户输入。
4. **查看器标签不贴图上**。上一轮实测贴图上只有 3.8–4.1:1。
5. **删除不提供撤销**，改为二次确认（原型是删除可撤销）。
