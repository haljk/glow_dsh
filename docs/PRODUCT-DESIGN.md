| 项 | 内容 |

---

## 1. 产品定位

**给非专业用户的一个"少调参数、多出成品"的本地图像工作台。**

它不是一个通用图像编辑器，也不是 prompt 编辑器。它把三件具体的事做成三条固定路径，并把一台局域网模型服务的"真实可用能力"翻译成人话。

### 1.1 不做什么

明确排除，以免功能蔓延：

- 不做图层、蒙版、笔刷等像素级编辑（当前服务不提供蒙版通道，见 §6）
- 不做多模型切换（换模型要走 ComfyUI，是另一条链路）
- 不做账号、云端同步、分享链接
- 不做密码/权限（归档只是"收起来"，不是保密）

### 1.2 命名

英文 **Glow**（光、发光），中文 **阁楼**（一个人的小工作室）。二者谐音，且分别对应"图像的光感"与"个人创作空间"，合起来正好是"在自己的阁楼里让图亮起来"。

## 2. 目标用户与场景

### 2.1 用户画像

- 会用电脑、会打字，但**不懂**「采样步数」「guidance」「负向提示词」「CFG」这类词
- 有真实的图要处理：社交配图、产品图、个人照片、素材图
- 能接受"等几分钟"，但不能接受"等完发现白等了"
- 单机单用户，不需要协作

### 2.2 三条主路径

| 场景 | 用户手里有什么 | 用户想做什么 |
| --- | --- | --- |
| ① 写一句话出图 | 什么都没有 | 从零得到一张图 |
| ② 单图精修 | 一张照片 | 换背景/换衣服/换发型…，**别的地方别动** |
| ③ 多图合成 | 两张以上素材 | 把 A 的人放进 B 的景、穿 C 的衣服 |

三条路径共用同一套尺寸、种子、队列与结果管理。

## 3. 设计原则

五条原则，每条都由一个具体的服务端事实或工程约束倒推而来，不是口号。

| 原则 | 来源事实 | 落地方式 |
| --- | --- | --- |
| **只暴露真的能调的东西** | `steps` 只能 6、`guidance` 只能 1.0、`negative_prompt` 被静默忽略 | 不做滑杆；把固定项以只读方式展示并解释原因 |
| **等待不能挂在请求上** | 一次精修 220–380 秒，任何短超时都会让结果作废；服务端后来专门加了队列服务承接长任务 | 提交只拿任务号，长耗时在服务端队列里跑，页面只轮询 |
| **替用户写他不会写的那句话** | "只改指定部分、其余锁住"是精修成败关键，普通人写不出来 | 9 个预设各自携带指令 + 按预设生成的冻结清单 |
| **比例和清晰度是两件事** | 编辑耗时由参考图张数主导，与画布尺寸关系不大 | 比例跟原图、清晰度选档，互不干扰 |
| **不承诺做不到的事** | 无蒙版 → 无法"物理保证"不变 | 界面明说"提示词约束，不是蒙版重绘" |

## 4. 信息架构

### 4.1 入口

侧边栏面板图标（`sidebar.panellist`，order 30）→ 主面板（`main` slot，key `glow`）。切换面板不影响正在跑的任务。

### 4.2 布局

```
┌──────────────────────────────────────────────────────────┐
│ 阁楼                       [出图服务·就绪] [写作助手·就绪] [重新检查] │
├────────────────────────┬─────────────────────────────────┤
│ ① 先选做什么            │  任务进度条（有任务时）            │
│  ┌─ 写一句话出图       │                                 │
│  ├─ 拿一张照片精修      │  本次结果                        │
│  └─ 多张图合在一起      │  ┌────┐ ┌────┐ ┌────┐           │
│ ② 写一句描述 / 放图片    │  │ 图 │ │ 图 │ │ 图 │           │
│   （随场景变化的控件）    │  └────┘ └────┘ └────┘           │
│   常用提示词 (n/5)      │                                 │
│   画面尺寸 / 更多设置     │  以前做的（最近 N 张）            │
│   模型服务（可折叠）      │  ┌────┐ ┌────┐                 │
│ ─────────────────────  │                                 │
│ ③ 开始 [生成图片]        │  归档箱（N）                     │
└────────────────────────┴─────────────────────────────────┘
```

左列固定宽 404px、独立滚动；**提交按钮固定在左列底部**（`.mw-footer` 不随内容滚走），因为精修场景控件总高可达 800–900px，按钮若跟随内容会落到首屏之外。

窄屏（<900px）自动改为上下堆叠。

### 4.3 节奏

界面用 ①②③ 三步引导，降低"这么多控件从哪开始"的压力。

## 5. 功能设计

### 5.1 场景一 · 写一句话出图

| 元素 | 行为 |
| --- | --- |
| 描述输入框 | 4 行文本域，接受大白话 |
| 「写不出来？帮我写详细一点」 | 调本地 LLM 扩写为完整提示词（模式 `expand`） |
| 风格/光线/镜头标签 | 点一下追加到描述末尾（各 6–7 个预设词） |
| 批量 | 1–2 张；服务端上限就是 2，种子依次 +1 |

### 5.2 场景二 · 单图精修

| 元素 | 行为 |
| --- | --- |
| 参考图 | 最多 2 张：第 1 张是要改的照片；第 2 张可选，用下拉指定「当作新背景／新衣服／只参考色调／只参考局部细节」 |
| ① 处理方式 | 9 个预设（见下表），可跳过 |
| ② 补充要求 | 一句白话，可跳过；可点「帮我写成精准的修改要求」由 LLM 改写（模式 `edit-instruction`） |
| 查看将发送的指令 | 把系统合成的指令展示给用户，`<Picture n>` 显示为「图 n」 |
| 尺寸 | 默认跟随原图比例 + 清晰度档（见 §5.5） |

**9 个预设及其允许改动范围**（`mayChange` 决定什么被写进"保持不变"清单）：

| 预设 | 允许改动 | 不变量（其余全部锁定） |
| --- | --- | --- |
| 换背景 | 背景、光照、色调 | 身份、表情、发型、姿态、镜头角度、清晰度、物体增删、主体位置 |
| 换衣服 | 服装其余部分 | 同上（背景与光照也保留） |
| 换发型 | 发型 | 同上 |
| 微调表情 | 表情 | 同上 |
| 换光线或时段 | 光照、色调 | 同上 |
| 去掉路人或杂物 | 物体、背景 | 不再声明"不增删物体" |
| 抠图换纯色底 | 背景 | 光照保留（纯色底不需重打光） |
| 老照片修复 | 清晰度 | 其余全锁，含年代感 |
| 证件照换底色 | 背景、光照、清晰度 | 其余全锁 |

> 设计要点：**冻结清单是生成的，不是写死的**。早期版本用一条固定句，导致「换光线」预设里同时出现"改光线"和"光照不变"；主体句也曾一边说"保留表情"、一边执行"改表情"。现在预设声明 `mayChange`，冻结句与主体句都由 `总表 − mayChange` 生成，面板还会显示「会改动：…」。

### 5.3 场景三 · 多图合成

| 元素 | 行为 |
| --- | --- |
| 参考图 | 最多 5 张（受单次时长约束，见 §6.3） |
| 每张图的用途 | 6 选 1：主体／背景／服装／色调与画风／构图与机位／局部细节 |
| 预设 | 不提供（合成靠用途声明 + 补充要求即可） |

用途直接决定指令句式，例如「以图 1 为主体，完整保留其身份…；把背景替换为图 2 中的场景」——模型不知道"哪张该留、哪张该借"，必须由用途显式告知。

### 5.4 提示词助手

接本地 LLM，三种模式 + 一种隐式模式：

| 模式 | 入口 | 输出 |
| --- | --- | --- |
| `expand` 扩写 | 场景一 | 一条完整生图提示词 |
| `refine` 润色 | — | 保留原意、去空话与否定句 |
| `variations` 变体 | — | N 条不同风格候选（按 `count` 裁剪，1–4） |
| `edit-instruction` 组织修改指令 | 场景二/三 | 精确的编辑指令，含"只改哪里+其余不变" |

所有模式共享同一套硬性约束（写进 system prompt）：

1. 只输出正文，不要解释与引号包裹
2. 必须落到可观察的视觉事实（材质、光线方向、构图、镜头）
3. 禁空话（"高质量""杰作""8K"）
4. **所有排除要求改写成正向陈述**，不得出现"不要/避免/没有/no/without/avoid"
5. 画面文字用引号原样写出并指定位置

第 4 条不是风格偏好，而是因为服务端 `negative_prompt` 无效——负向表述写进去等于没写。

### 5.5 尺寸与清晰度

**场景一**：7 个带名字的预设尺寸（方形推荐、竖版人像、手机壁纸、电脑壁纸、横版照片、超清横版、小图试手）+ 自定义。

**场景二/三**：默认**继承第一张参考图的长宽比**，用户只选清晰度。

| 档位 | 像素预算 | 用途 |
| --- | --- | --- |
| 快速 | 约 0.41 MP（640²） | 试构图 |
| **推荐**（默认） | 约 1.05 MP（1024²） | 模型训练区间 |
| 高清 | 约 2.07 MP（1440²） | 要放大看细节 |

拟合算法 `fitSize(原图比例, 目标像素预算)` 输出服务端合法尺寸（32 倍数、256–2048）：先按宽推算、再按高推算，取比例偏差更小的一侧。实测 8 种原图比例 × 3 档共 24 组全部合法，最大比例偏差 **1.6%**（超宽 5:1 因 2048 上限被截，属已知边界）。

用户可随时切「自己指定画面尺寸」，也可切回自动。

### 5.6 结果区

| 操作 | 行为 |
| --- | --- |
| 点缩略图 | 进全屏查看器；有参考图的编辑结果**直接进对比视图** |
| 看实际像素 | 1:1 原始像素、可滚动 |
| 对比参考图 | **并排**（参考图与结果各占一栏）或**滑动**（叠放 + 拖动分界线） |
| ← → / Esc | 翻页 / 关闭；点空白处也关闭 |
| 按这张的参数重做 | 回填描述、尺寸、种子，并切到对应场景 |
| 继续改这张 | 把它作为下一轮素材（不下载再上传） |
| 下载 / 删除 | 删除连同 `.json` 元数据与参考图副本一并清除 |
| 归档 | 见 §5.7 |

缩略图按真实画幅比例显示（不强行正方形），卡片上显示尺寸、耗时、你的原话；若模型改写提示词，额外显示"模型实际采用"。

### 5.7 归档

- 结果卡「归档」→ 写入该结果的 `.json`（`archived: true`），**文件不移动、不删除**
- 主列表（本次结果 / 以前做的）按 `archived` 过滤
- 统一入口在结果区底部「归档箱（N）」，点开才读取；也可在此「移出归档」
- 删除结果时会连带删除参考图副本

### 5.8 常用提示词

- 上限 **5 条**，存在输出目录的 `favorites.json`
- 「把上面这句存为常用」→ 存当前输入框内容；点条目 → 填回输入框；× → 删除
- 存满 5 条时**拒绝新增并提示先删一条**，不做静默淘汰
- 内容重复时识别为重复，不重复入库

### 5.9 模型服务管理

面板内「模型服务」（可折叠），改动即时生效，无需重启：

| 项 | 默认 | 校验 |
| --- | --- | --- |
| 出图方式 | 后台排队 | `queue` / `sync` 二选一，非法值报错 |
| 队列服务地址 | `http://127.0.0.1:9742` | 必须 http/https，自动去尾斜杠 |
| 模型服务地址（回滚用） | `http://127.0.0.1:9741` | 同上；直连方式下的目标，也用于读尺寸上限 |
| 提示词服务地址 | `http://127.0.0.1:9739` | 同上 |
| 模型名 | `default_model` | 非空 |
| 一张图最多等多久 | 1800 秒 | 60–7200 秒 |
| 图片保存目录 | `~/Pictures/glow` | 留空用默认 |

操作：**测试连接**（分别探两个 `/health`，不落盘）、**保存并生效**、**恢复默认地址**。

持久化在 `~/.glow/settings.json`，**不在插件目录内**，因此仓库天然不含任何内网地址。启动时若该文件被手改坏，会退回插件行 `config`、再退回内置默认，不会导致插件起不来。

旧设置（只有「出图服务地址」且端口 9741）在首次加载时自动迁移：模式置为 `queue`、端口改 9742、原地址写入回滚地址并记录 `migratedFrom`，迁移结果立刻回写文件。

### 5.10 任务队列与进度

- 提交只创建任务，立即返回（实测 65 ms）；页面每 2.5 秒轮询
- 本地任务状态：`queued → running → done | failed`，同时带着服务端任务的 `remoteStatus`
- 界面显示：排队中（前面还有 N 个）／正在做（已用 N 秒、大约还要 N 秒、百分比）／完成
- 空闲时可继续提交，自动排队；本机最多同时跟进 20 个任务，避免一个应用占满服务端 64 个位置
- 串行化交给服务端队列（单 worker），本机不再抢那一把锁；429 读 `Retry-After` 后重提，同一任务用同一个 `Idempotency-Key`，重提不会多出一张图
- 未完成任务号写入 `~/.glow/jobs.json`，DSH 重启后接着查、接着取图
- 只有排队中的任务能取消；已开跑的返回 409 并如实告知「只能等它跑完」

## 6. 能力边界与服务端事实

### 6.1 参数真伪

| 字段 | 真实 | 说明 |
| --- | --- | --- |
| `prompt` | ✅ | 中英文，非空 |
| `size` | ✅ | `WxH`，32 倍数，256–2048；非 32 倍数**静默吸附**并回包 `adjusted:true` |
| `n` | ✅（夹取） | >2 静默变 2，种子 +1 |
| `seed` | ✅ | 同提示词+同尺寸+同种子 = **字节级相同**（实测哈希一致） |
| 参考图 | ✅ | 1–16 张，`<Picture n>` 按序引用 |
| `steps` | ❌ | 固定 6，其他值 400 |
| `guidance` | ❌ | 固定 1.0，其他值 400 |
| `negative_prompt` | ❌ | 被接受但忽略 |
| `quality` / `style` / 未知字段 | ❌ | 被接受但忽略 |

### 6.2 实测耗时（Apple silicon / 64 GB，私网）

| 任务 | 尺寸 | 耗时 |
| --- | --- | --- |
| 文生图 | 256²–512² | ~32 s |
| 文生图 | 1024² | ~72 s |
| 文生图 | 2048² | >3 min |
| 编辑 1 张参考图 | 256² | ~156 s |
| 编辑 1 张参考图 | 1024² | ~220 s |
| 编辑 2 张参考图 | 256²/512²/1024² | ~300–380 s |

两条结论直接塑造了产品：

1. **编辑耗时由参考图张数主导**（每多一张约 +150 s），与画布尺寸关系不大 → 所以"保持大画布 + 限制张数"是对的
2. **小画布对编辑不是提速而是毁图**（256² 退化为色块）→ 所以推荐档就锁在 1024² 等效

### 6.3 由此形成的硬约束

| 约束 | 取值 | 依据 |
| --- | --- | --- |
| 单次批量 | 2 | 服务端上限 |
| 精修参考图 | 2 | 产品简化（1 主体 + 1 可选参考） |
| 合成参考图 | 5 | 6 张已达 930 s，超过 900 s 单次上限 |
| 单张参考图体积 | 8 MB | 传输与内存 |
| 参考图合计 | 60 MB | 96 MB 请求体上限留余量 |

## 7. 系统架构

### 7.1 分层

```
浏览器（React 面板）
   │  fetch /api/glow/*（同一 origin，POST 带 x-glow 头）
   ▼
DSH Host 进程（index.js）
   ├─ 路由分发 + 同源校验
   ├─ 任务跟进（提交 → 轮询 → 取图，保留 40 条）
   ├─ 指令合成（预设 + 角色 + 补充 + 冻结清单）
   ├─ 队列服务调用（node:http，非 fetch）
   └─ LLM 调用 / 文件落盘 / 目录扫描
        │
        ├─► 队列服务（:9742）  image-job-queue（排队 + 持久化）
        │        └─► 图像服务（:9741）  MiniMax-H3-Image（直连模式下由 Host 直接调）
        ├─► LLM 服务（:9739）  OpenAI 兼容 chat
        └─► 本地磁盘：图片目录 + ~/.glow/settings.json + ~/.glow/jobs.json
```

### 7.2 路由表

| 方法 | 路径（前缀 `/api/glow`） | 用途 |
| --- | --- | --- |
| GET | `/settings` | 当前设置 + 默认值 + 文件路径 |
| GET | `/capabilities` | 两个服务探活 + 尺寸网格 + 队列状态 |
| GET | `/presets` | 9 个预设（含 `changes`）+ 6 个用途 |
| GET | `/history?limit&archived` | 结果列表（`archived=0｜1｜all`）+ 双侧计数 |
| GET | `/favorites` | 常用提示词 |
| GET | `/jobs` · `/jobs/<id>` | 任务列表 / 单任务 |
| GET | `/file/<name>` | 结果、参考图副本 |
| POST | `/generate` · `/edit` | 提交任务 |
| POST | `/preview` | 只合成指令，不出图 |
| POST | `/prompt` | LLM 提示词/指令生成 |
| POST | `/settings` · `/settings/reset` · `/settings/test` | 设置读写与探活 |
| POST | `/jobs/clear` | 清理已完成任务 |
| POST | `/jobs/cancel` | 取消排队中的任务（已开跑返回 409） |
| POST | `/favorites` · `/favorites/remove` | 常用提示词增删 |
| POST | `/archive` | 归档 / 移出归档 |
| POST | `/delete` | 删除结果（含元数据与参考图副本） |

### 7.3 任务跟进

单个 `tick()` 循环（每 4 秒），内存态 + 磁盘留痕：

```
enqueue(job) → jobs.set(job) → tick()
tick():
  ├─ 读回：对每个已有服务端任务号的任务 GET 状态 → queued/running/done/failed/canceled
  ├─ 取图：succeeded → 下载 result.png（n=2 时还有 result-1.png）→ 落盘 → done
  └─ 提交：本地未提交的任务，最多 20 个同时跟进；429 按 Retry-After 退避重提
```

- 进度（百分比、ETA、前面还有几个）直接取服务端的 `progress`，不再本地估算
- 完成态保留 40 条（`JOB_HISTORY_LIMIT`），`/jobs` 返回最近 40 条
- 未完成任务号写入 `~/.glow/jobs.json`：关闭应用后重开，任务仍能接着查、接着取图
- 直连模式（`imageMode=sync`）保留旧的阻塞执行路径，任务同样在后台线程里跑

## 8. 关键工程决策

| 问题 | 决策 | 结果 |
| --- | --- | --- |
| 精修要 5 分钟，HTTP 请求等不起 | 改成后台任务 + 轮询 | 切页面/刷新/最小化都不中断 |
| 实测 306 秒处 `fetch failed` | 长调用改走 `node:http` | 同一张图 381 秒正常完成。原因是 undici 自带 300 秒响应头超时，`AbortSignal` 无法延长 |
| 服务正忙时探活变慢会把合法请求判成 500 | 探活降级为非致命，先做本地校验 | 非法尺寸 24 ms 返回 400，不再伪 500 |
| 参考图模式尺寸靠用户填宽高 | 继承原图比例 + 清晰度档 | 用户不再算像素；24 组拟合全部合法 |
| 冻结句与预设互相矛盾 | 预设声明 `mayChange`，句子生成 | 矛盾消除，且面板显示"会改动" |
| 归档状态放哪 | 写进结果自身 `.json` | 无独立数据库，删文件即删记录 |
| 常用提示词放哪 | 输出目录 `favorites.json` | 与图片同处备份；上限 5 条防膨胀 |

## 9. 状态、错误与安全

### 9.1 错误呈现

| 场景 | 用户看到 |
| --- | --- |
| 服务未连接 | 顶部状态点变红，悬停显示原因（排队方式下会区分「队列没连上」和「队列在等模型恢复」） |
| 队列满（429） | 「队列已满，约 30 秒后自动重试」，按服务端 `Retry-After` 退避，不打扰用户 |
| 服务忙（409，仅直连方式） | 「图像服务正忙（同一时刻只能跑一张）」+ 自动退避重试 |
| 取消已开跑的任务 | 「已经开始生成了，只能等它跑完（服务端不支持中断）」；被取消的任务不算失败，不进红框 |
| 结果过期 | 「结果已过期（队列结果只保留 7 天）」——正常使用碰不到，因为成功即下载 |
| 取图失败 | 「图已经生成好，取图没成功（第 N 次），稍后重试」，按轮询节奏自动重试 |
| 超时 | 「等了 30 分钟还没拿到结果」（排队方式，含排队时间）/「等待图像服务超时」（直连方式） |
| 尺寸非法 | 即时提示 + 建议可用的对齐值 |
| 比例/张数超出时长 | 提交前拦截并说明原因（仅直连方式，排队方式没有单次时长上限） |
| 轮询失败 | 明确报错并解除按钮锁定（不会永久卡在"1 个任务在跑"） |
| LLM 空返回 | 「写作助手这次没有写出内容，请再点一次」 |

### 9.2 安全

- 路由挂在 `/api/glow` 前缀下，**位于共享 `/api` 网关之外**，因此自带校验：
  - **请求的 Host 必须是环回地址或本服务实际监听的地址**，否则 403。这一条专门防 **DNS rebinding**：恶意域名解析到 `127.0.0.1` 后浏览器仍视作同源，下面两道都会放行，只有校验 Host 本身能挡住
  - 写操作必须带 `x-glow: 1` 头（跨站表单无法伪造）
  - `Origin` 与 `Host` 不一致则 403
  - 读操作按 `Sec-Fetch-Site` 与 `Referer` 校验同源（`<img>` 无法带头，故不能只靠头）

  四道检查的分工：Host 校验负责"你确实是冲本机来的"，其余三道负责"你确实是从本页面来的"。它们合起来防的是跨站与重绑定，**但不等于身份认证**——本机上的任何进程仍可访问，因为本机进程本来就能直接读写这些文件。

- 文件名只接受 basename + `[A-Za-z0-9._-]+.(png|json)`，杜绝路径穿越
- 请求体上限 96 MB
- 服务无鉴权、无 TLS，仅限环回/私网；本插件同样不做公网暴露
- 无遥测、无外联；除两个模型服务外不访问任何地址

## 10. 已知限制

1. **"别的地方不动"是提示词约束，不是蒙版重绘**。实测换背景时脸、发型、服装、姿态都保留，但脸型仍可能轻微漂移；关键用途应多出几张挑。
2. 出图服务**同一时刻只能跑一个任务**，连续提交会排队，等待叠加。排队方式下排队在服务端（上限 64），满员返回 429 并按 `Retry-After` 退避重提。
3. **结果文件服务端只保留 7 天**。插件在任务成功时立刻下载转存到本地目录，因此正常使用无感；本地目录被清空后，那份图 7 天后也取不回来。
3. 小尺寸对编辑是毁灭性的，推荐档以下只当预览。
4. 换背景/抠图时，复杂发丝边缘可能出现毛边。
5. 关闭整个应用会中断进行中的任务（已出图不受影响）。
6. 界面文案以中文为主（少量标签走 locale 服务），未做完整英文版。
7. 每张编辑结果会多存一份参考图副本，占用磁盘（删除结果时一并清理）。
8. 参考图上限 16 是服务端能力，本产品因时长约束收紧到 2 / 5。
